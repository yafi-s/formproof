# Evaluation contract

`fixtures/cases.json` holds independent field truth and the native-control scenarios. `tests/browser_check.py` renders those declarations into six controlled HTML pages and exercises the actual scanning, planning, approval and write functions in Chromium. The form submit event is prevented and counted; all exercised fills leave that count at zero. The UI uses a Chrome API emulator in a separate page realm; no extension is installed.

The field corpus contains 64 controls: 36 have an available verified fact and supported unambiguous native representation; 28 require abstention because of unknown/narrative wording, missing facts, ambiguous options, conflicting hints, unsupported controls, editability or existing data. All profile values are fictional and supplied by the evaluator. Sensitive fixture answers are entered as explicit user facts and the suite separately tests that consent blocks their use.

Precision = correct accepted proposals / accepted proposals. Supported recall = correct accepted proposals / 36 supported fields. Abstention rate = skipped controls / 64. Required correction count = accepted proposals with a wrong or unsupported value. Overall fill coverage is 36/64 (56.25%); supported recall of 100% does not mean every application field is supported. The recorded observation is 36/36 accepted values correct, 28/64 abstained, zero corrections. This small curated corpus is not a statistical guarantee.

The baseline receives the same verified values and respects basic disabled/hidden/prefilled restrictions. It maps substrings in field name/id hints rather than semantic labels, has no sensitive defaults, and picks exact options. It produced 14 correct values out of 18 proposals, requiring four corrections and covering 14/36 supported fields. Baseline results are included row by row; this compares two local algorithms, not commercial autofill products.

The browser suite has 29 checks covering changed labels, form actions, prefilled values, disabled/hidden/removed fields, altered options, replayed approval, event-driven mid-fill field and URL/action mutations, newly added radio controls, per-field destination display, frame-local nonce rejection, popup import/conflict/ranking/verification/lock/unlock/delete, delayed storage/import/scan deletion races and sensitive-review/apply. The seven actual-demo checks also cover canonical GET/HEAD allowlisting, encoded traversal, failed-save deletion and inert HTML rendering. Screenshots were visually inspected. Node tests isolate parser provenance, idempotency, conflicts, sensitive-key restrictions, hint contradictions, exact option mapping, encryption tampering, deletion and changed profile revisions. Importer tests exercise a real two-page synthetic PDF text layer, a textless PDF refusal and text-format failures.

`parser_evaluate.mjs` compares candidate values against declared truth on two explicitly labeled resumes and one conventional sectioned resume: 31/31 proposals correct in this small fixture set. Unlabeled PDFs, multilingual resumes, complex columns and scanned documents are not qualified by this result.

The entry-time experiment has three trials on the same 14 native fields (253 characters). The scripted baseline types with a declared 20 ms/character delay and waits 100 ms per field. The comparison invokes planning, explicit programmatic approval and application. Its elapsed wall times include Playwright calls. These artificial delays are assumptions; resume import, fact verification, reading/review/cognition, choice of resume, attachments and submission are excluded. Raw differences demonstrate mechanical entry behavior only. Human savings remains null in the report and must not become a resume/product claim.

Reproduction: run `verify.ps1` in this folder using the existing optional Python packages and local Chromium installation. Results include timestamps and exact Node/Python/browser/platform versions. Rerunning updates local result files; copy evidence before rerunning if you need historical comparisons. The uninstalled extension requires a separate installation/lifecycle review before real-site use. All named commercial ATS sites remain unverified.
